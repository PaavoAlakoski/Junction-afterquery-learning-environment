The mistake is a decision, not missing information

The agents spend less on stock than the reference and far more on unfilled demand.

"There is a large excess, and holding cost is the main concern. […] I'd rather let the retailer run lean." Sonnet 5.5, scenario 3, week 15. Ten weeks later the retailer was empty.
  • It was told the price. A unit short costs 10; a unit held costs 0.25 to 1.
  • It was told the risk. The rules say demand may step up by 40–90% between weeks 9 and 35.
  • It was told the delay. New production needs up to 9 weeks to reach customers, so the stock must already be in the pipeline.
  • The reference uses the same inputs: the rules text and the same weekly state.

One command reproduces every number

Python standard library only for the simulator, baselines and reference. Deterministic per seed.

python evaluate.py                 # reference + baselines
python evaluate.py --agent claude  # three agent runs
python mcp_server.py --seed 1      # MCP server for the harness
python -m unittest -v              # exploit and MCP checks
python train.py                    # retrain the small policy
python replay.py                   # week-by-week replay page

Every agent reply is saved with the results, so each failure can be read back.

What we have not shown

  • Sonnet was run once; five scenarios is a small suite.
  • The reference scores only 21 on scenario 1, where demand drifts down and the naive rule is hard to beat.
  • Our agent runs used the Anthropic API, not the MCP server.
  • The MCP server is tested with the official MCP client, not yet with the AfterQuery harness.
